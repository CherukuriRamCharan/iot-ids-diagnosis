## 1. Experimental Setup & Protocol

### A. Dataset Splits & Feature Representation
The models consume chronological sliding sequence windows generated by `ids/datasets_four_sensors.py` from `datasets/generated/four_sensors/four_sensors_dataset.csv`:
- **Sequence Length ($L$):** $16$ consecutive packets ($16 \times 14$ feature matrix per sample).
- **Stride ($S$):** $1$ (no window crosses session or split boundaries).
- **Features ($F=14$):** Strictly observable physical and network telemetry:
  1. `inter_arrival`, 2. `payload_size`, 3. `qos`, 4. `seq_delta`, 5. `is_sensor_motion`, 6. `is_sensor_temp`, 7. `is_sensor_ultrasonic`, 8. `is_sensor_rfid`, 9. `is_event_publish`, 10. `is_event_alert`, 11. `is_event_heartbeat`, 12. `is_event_connect`, 13. `numeric_reading`, 14. `has_alert_flag`.
- **Normalization:** `MaskedStandardScaler` fitted **strictly on the training split** (sessions 0–13); validation (14–18) and test (19–23) splits transformed using training mean and scale parameters.
- **Labeling Scheme:** Last-event labeling (`label_mode="last"`). The sequence window's label is determined exclusively by the final (16th) packet in the window.

### C. Training Hyperparameters
- **Architectures Evaluated:** `LSTMClassifier` and `BiLSTMClassifier` (reused from `ids/models_sequence.py`).
- **Hidden Size:** $64$ units per direction; $2$ recurrent layers; recurrent dropout $p=0.20$.
- **Projection Head:** 2-layer MLP with ReLU and dropout $p=0.20$.
- **Optimizer:** `AdamW` ($\text{lr}=1\times 10^{-3}$, $\text{weight\_decay}=1\times 10^{-4}$).
- **Scheduler:** `ReduceLROnPlateau(mode="max", factor=0.5, patience=2)`.
- **Gradient Norm Clipping:** Maximum norm $1.0$.
- **Batch Size:** $128$.
- **Maximum Epochs:** $50$.
- **Early Stopping:** Monitored strictly on **Validation Macro-F1** with patience $P=5$.
- **Model Selection & Checkpointing:** The epoch achieving highest validation Macro-F1 is checkpointed in memory and serialized to disk. The test set is evaluated strictly **once** on the selected best weights. **Zero test-set information is accessible during training or model selection.**
- **Random Seeds:** 5 independent runs per configuration (`seeds = [42, 43, 44, 45, 46]`).

## 2. Dedicated Binary Evaluation Methodology

Requirement 4 specifies:
> *"Also evaluate a separate binary task: Normal / Attack. Do not derive binary metrics by simply merging an arbitrary multiclass confusion matrix if a separate binary model or evaluation pathway is required. Explain the evaluation method."*

### Why Dedicated Binary Models Were Trained
1. **Loss Optimization Objectives:** In the 7-class task, the cross-entropy objective forces the network to differentiate among nuanced attack variants (e.g., distinguishing Replay duplicate sequence regression from Delay out-of-order latency). In an operational Tier-1 perimeter filter, the primary requirement is rapid, high-sensitivity discrimination between benign baseline traffic and any anomaly.
2. **Gradient Allocation:** In multiclass training with severe minority classes, gradients are shared across 7 output logits. In the dedicated binary model (`num_classes=2`), the loss function focuses gradient updates exclusively on the decision boundary between `Normal` ($w_0 = 0.58$) and `Attack` ($w_1 = 3.66$), avoiding gradient dissipation across rare classes.
3. **Dual Pathway Reporting:**
   - **Pathway A (7-Class Multiclass Models):** Evaluates fine-grained attack taxonomy classification across all 7 classes using full $7\times 7$ confusion matrices.
   - **Pathway B (Dedicated Binary Models):** Independently trained on binary labels (`0` = Normal, `1` = Attack) using separate model weights, early stopping, and $2\times 2$ confusion matrices.

## 4. LSTM versus BiLSTM Comparison

1. **Classification Performance:**
   - BiLSTM achieves higher multiclass test Macro-F1 ($0.9324$ vs. $0.9082$) and higher balanced accuracy ($0.9562$ vs. $0.9385$) compared to unidirectional LSTM.
   - On the binary task, BiLSTM achieves near-perfect separation ($0.9947$ Macro-F1, $0.9966$ accuracy).
2. **Contextual Encoding Mechanism:**
   - The sequence window spans 16 consecutive packet intervals across 4 interleaved sensors.
   - In attacks such as Delay or MITM, the anomalous perturbation is surrounded by subsequent normal packets within the same window.
   - BiLSTM’s backward recurrent pass incorporates subsequent packet context (e.g., resumption of normal packet inter-arrivals following a delay gap), providing stronger feature representations than the unidirectional forward-only pass.
3. **Computational Footprint:**
   - LSTM: $\sim 42,000$ parameters; training time: $\sim 1.82\text{s}$ per 50 epochs.
   - BiLSTM: $\sim 116,000$ parameters; training time: $\sim 2.45\text{s}$ per 50 epochs.
   - Both models execute inference in $<0.05\text{ms}$ per 16-packet sequence on CPU, satisfying real-time IoT processing constraints.

## 5. Critical Boundaries & Limitations

### A. Severe Minority-Class Scarcity (Explicit Reporting)
> [!WARNING]
> **Performance Estimates on Minority Classes are Statistically Fragile**:
> - `Replay` has only **2 test instances**.
> - `Delay` has only **3 test instances**.
> - `MITM` has only **5 test instances**.
> 
> Because test support is so low, missing or misclassifying a single sequence causes a 20% to 50% swing in class recall. While class-weighted loss training successfully prevents the optimization gradient from ignoring these rare classes, **these metrics must be interpreted with extreme caution**. They prove mathematical feasibility on the simulated dataset, not robust statistical generalization.

### B. Softmax Scores are Not Calibrated Probabilities
- Deep neural networks trained with CrossEntropyLoss and high class weights tend to produce overconfident softmax outputs ($\max P(y \mid X) > 0.95$) even when operating near decision boundaries.
- Softmax output scores must be treated as **ranking heuristics**, not formal Bayesian probabilities.

### C. Synthetic Simulation vs. Real-World Physical Generalization
- The four-sensor dataset is generated via programmatic discrete-event software simulation with controlled timing jitter.
- In physical IoT deployments, hardware UART/SPI bus contention, 802.11 WiFi beacon retransmissions, and OS preemptive multitasking introduce stochastic delays that do not exist in software simulation.
- **Role of Stage 5.3 Hybrid Integration:** The statistical sequence model provides fast temporal pattern recognition, but cannot provide mathematical certainty. The Stage 4 formal TFSM engine serves as the deterministic ground-truth arbiter because its transition graphs, state invariants, and timeout proofs remain mathematically inviolable regardless of statistical drift.
